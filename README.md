# govbr-ds-validator

Proof-of-concept for the thesis _"Um Framework de Validação de Interfaces Baseado em Agentes de IA e Protocolo MCP"_.

Demonstrates that an AI agent orchestrated via MCP detects **Design System and accessibility violations that axe-core and eslint-plugin-jsx-a11y miss by design** — because those tools operate on individual elements without DS-specific token knowledge, e-MAG rules, or cross-element reasoning.

---

## Architecture

```
┌─────────────────────────────────────┐
│  AI Agent (Claude)                  │
│  orchestrates via MCP               │
└────────┬──────────────┬─────────────┘
         │              │
         ▼              ▼
┌─────────────┐  ┌───────────────────────┐
│ @playwright │  │ govbr-ds MCP server   │
│    /mcp     │  │                       │
│             │  │ get_design_tokens     │
│ DOM + a11y  │  │ get_emag_rules        │
│ tree        │  │ get_page_rules        │
│             │  │ get_component_examples│
│             │  │ inspect_computed_     │
│             │  │   styles (+ :focus)   │
└─────────────┘  └───────────────────────┘
         │              │
         └──────┬───────┘
                ▼
   ┌────────────────────────┐
   │  Sample app            │
   │  localhost:3000        │
   │                        │
   │  26 test cases:        │
   │  TC-B-01…TC-B-13       │
   │  TC-F-01…TC-F-13       │
   └────────────────────────┘
```

The agent is the reasoning layer. The MCP servers supply raw data (DOM state, DS token values, e-MAG rules). No validation logic is hard-coded — the agent reasons from the evidence.

## Prerequisites

- **Node.js 18+** (tested on v25) — `nvm use 25`
- **Claude Code** with two MCP servers registered (see below)

---

## Setup

### 1. Install dependencies

```bash
cd mcp-server && npm install
cd app && npm install
cd scripts && npm install   # also runs: playwright install chromium
```

### 2. Generate DS tokens

```bash
cd scripts && node parse-tokens.js
# → mcp-server/data/tokens.json
```

### 3. Register MCP servers in Claude Code

Add to your Claude Code user config (`~/.claude/claude_desktop_config.json` or equivalent):

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    },
    "govbr-ds-validator": {
      "command": "node",
      "args": ["/absolute/path/to/govbr-ds-validator/mcp-server/index.js"]
    }
  }
}
```

## Running

### Start the sample app

```bash
cd app && npm run dev
# → http://localhost:3000
```

### Formal evaluation (thesis scoring)

```bash
# 1. In Claude Code — evaluates all 26 cases, writes agent-results.json
evaluate all

# 2. In the app — click ▶ Executar axe-core on the Matriz de Detecção tab
#    or from terminal:
cd scripts && node run-axe.js

# 3. Score all tools against ground-truth
cd scripts && npm run score
cd scripts && npm run score:verbose   # per-case breakdown
```

### Ad-hoc validation

| Command | What it validates |
|---|---|
| `validate http://localhost:3000` | Full report — a11y + tokens (both pages) |
| `validate the form at http://localhost:3000` | e-MAG form compliance only |
| `check tokens at http://localhost:3000` | Token compliance only |

## MCP server tools

| Tool | Description |
|---|---|
| `get_design_tokens` | DS token registry (colors, typography, radii) + hex→token reverse lookup |
| `get_emag_rules` | e-MAG v3.1 — all 6 sections, all rules, WCAG mappings |
| `get_page_rules` | DS structural/UX guidelines (page anatomy, form patterns, grid, WAI-ARIA) |
| `get_component_examples` | Canonical DS HTML examples from installed `@govbr-ds/core` package |
| `inspect_computed_styles` | Headless browser → computed CSS per element, including focus-state styles |

## Key finding

**14 of 20 violation cases are invisible to both axe-core and eslint-a11y.** The agent detects all 20 by combining capabilities no single static tool has simultaneously:

1. **Token knowledge** — knows the exact hex values, font names, and radius values that constitute valid DS tokens; detects off-by-one color errors, wrong fonts, non-token radii, and suppressed focus outlines
2. **e-MAG awareness** — knows Brazilian government accessibility rules (required field semantics, format hints, error linkage, visible labels) that WCAG and axe-core do not cover
3. **Cross-element reasoning** — evaluates elements in relation to each other (button order, duplicate accessible names, broken ARIA references, context-dependent semantic correctness)
