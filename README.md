# govbr-ds-validator

Proof-of-concept for the thesis _"Um Framework de Validação de Interfaces Baseado em Agentes de IA e Protocolo MCP"_.

Demonstrates that an AI agent orchestrated via MCP detects **Design System and accessibility violations that axe-core and eslint-plugin-jsx-a11y miss by design** — because those tools operate on individual elements without DS-specific token knowledge, e-MAG rules, or cross-element reasoning.

---

## Architecture

```
┌─────────────────────────────────────┐
│  AI Agent (Claude)                  │
│  orchestrates via MCP               │
└────────┬──────────────┬─────────────┘
         │              │
         ▼              ▼
┌─────────────┐  ┌───────────────────┐
│ @playwright │  │ govbr-ds MCP      │
│    /mcp     │  │ server            │
│             │  │                   │
│ DOM + a11y  │  │ get_design_tokens │
│ tree        │  │ get_emag_rules    │
│             │  │ inspect_computed  │
│             │  │ _styles           │
└─────────────┘  └───────────────────┘
         │              │
         └──────┬───────┘
                ▼
   ┌────────────────────────┐
   │  Sample app            │
   │  localhost:3000        │
   │                        │
   │  20 test cases:        │
   │  TC-B-01…TC-B-11       │
   │  TC-F-01…TC-F-09       │
   └────────────────────────┘
```

The agent is the reasoning layer. The MCP servers supply the raw data (DOM state + DS token values + e-MAG rules). No validation logic is hard-coded — the agent reasons from the evidence.

## Prerequisites

- **Node.js 18+** (tested on v25) — `nvm use 25`
- **Claude Code** with two MCP servers registered (see below)

---

## Setup

### 1. Install dependencies

```bash
# MCP server
cd mcp-server && npm install

# Sample app
cd app && npm install

# Axe baseline script
cd scripts && npm install   # also runs: playwright install chromium
```

### 2. Generate DS tokens

```bash
cd scripts && node parse-tokens.js
# → mcp-server/data/tokens.json
```

### 3. Register MCP servers in Claude Code

Add to your Claude Code user config (`~/.claude/claude_desktop_config.json` or equivalent):

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    },
    "govbr-ds-validator": {
      "command": "node",
      "args": ["/absolute/path/to/govbr-ds-validator/mcp-server/index.js"]
    }
  }
}
```

## Running

### Start the sample app

```bash
cd app && npm run dev
# → http://localhost:3000
```

### Run axe-core baseline

Either click **▶ Executar axe-core** on the Matriz de Detecção tab, or from the terminal:

```bash
cd scripts && node run-axe.js
# default: APP_URL=http://localhost:3000
# override: APP_URL=http://localhost:3001 node run-axe.js
```

Results are written to `results/axe-results.json` and `app/public/axe-results.json` (picked up live by the app).

### Run agent validation

In Claude Code, with both MCP servers running:

| Command | What it validates |
|---|---|
| `validate http://localhost:3000` | Full report — a11y + tokens (both pages) |
| `validate the form at http://localhost:3000` | e-MAG form compliance only |
| `check tokens at http://localhost:3000` | Token compliance only |

## Test cases

### Buttons (`/` — Botões tab)

| Case | Violation | axe | eslint | Agent |
|---|---|:---:|:---:|:---:|
| TC-B-01 | ✅ Reference | — | — | — |
| TC-B-02 | Icon button without accessible name | ✓ | ✓ | ✓ |
| TC-B-03 | `<div>` used as button | ✗ | ✗ | ✓ |
| TC-B-04 | `disabled` attr without `aria-disabled` | ✗ | ✗ | ✓ |
| TC-B-05 | Token color off by 1: `#1352b4` vs `#1351b4` | ✗ | ✗ | ✓ |
| TC-B-06 | Font override to Arial (wrong token) | ✗ | ✗ | ✓ |
| TC-B-07 | `br-button` without variant class | ✗ | ✗ | ✓ |
| TC-B-08 | Danger button without paired cancel | ✗ | ✗ | ✓ |
| TC-B-09 | `aria-label` contradicts visible text | ✗* | ✗ | ✓ |
| TC-B-10 | `border-radius: 6px` (not a DS token) | ✗ | ✗ | ✓ |
| TC-B-11 | ✅ Reference (icon with aria-label) | — | — | — |

### Forms (`/` — Formulário tab)

| Case | Violation | axe | eslint | Agent |
|---|---|:---:|:---:|:---:|
| TC-F-01 | ✅ Reference | — | — | — |
| TC-F-02 | Label `for`/`id` mismatch | ✓ | ✓ | ✓ |
| TC-F-03 | Placeholder-only input (no `<label>`) | ✗** | ✓ | ✓ |
| TC-F-04 | Required `*` in label without `aria-required` | ✗ | ✗ | ✓ |
| TC-F-05 | CPF field without format hint (e-MAG 6.5) | ✗ | ✗ | ✓ |
| TC-F-06 | Error message not linked via `aria-describedby` | ✗ | ✗ | ✓ |
| TC-F-07 | Destructive action using `primary` instead of `danger` | ✗ | ✗ | ✓ |
| TC-F-08 | Button order reversed: primary before secondary | ✗ | ✗ | ✓ |
| TC-F-09 | Select with `aria-label` only, no visible `<label>` | ✗ | ✗ | ✓ |

> \* axe has the `label-content-name-mismatch` rule (WCAG 2.5.3) but it is tagged `experimental` and excluded from default runs.
>
> \*\* axe accepts `placeholder` as a valid accessible name per ARIA spec. e-MAG 6.2 and eslint-a11y do not.

## MCP server tools

| Tool | Description |
|---|---|
| `get_design_tokens` | gov.br DS token registry (colors, typography, spacing, radii) + hex→token reverse lookup |
| `get_emag_rules` | e-MAG v3.1 — all 6 sections, all rules, WCAG mappings |
| `inspect_computed_styles` | Launches headless browser, returns computed CSS for all interactive elements |

---

## Key finding

**16 of 18 violation cases are invisible to axe-core in a default run.** The agent detects all 18 by combining three capabilities no single static tool has simultaneously:

1. **Token knowledge** — knows the exact hex values, font names, and radius values that constitute valid DS tokens
2. **e-MAG awareness** — knows Brazilian government accessibility rules that WCAG and axe-core do not cover
3. **Cross-element reasoning** — evaluates elements in relation to each other (button order, paired cancel buttons, error message associations)
